# Preparing the QNAP NAS for Photosort (local network and Tailscale)

Procedure for **phase 0b** of the plan [`2026-11-17-nas-local-connection-plan.md`](superpowers/plans/2026-11-17-nas-local-connection-plan.md). Only Tailscale is installed on the NAS: we create an account with minimal rights, restrict access through the Tailscale ACLs, then mount the share. Steps 1 to 6 and 9 to 10 do not change; step 7bis replaces mounting through the Finder when going through Tailscale.

**Duration**: 30 to 45 minutes. **Prerequisites**: administrator access to QTS (browser), Mac on the same network as the NAS.

## Principle

Photosort runs on the Mac. The `photosort` account can:

| Folder | Right |
| --- | --- |
| Input (loose iPhone photos) | **Read-only** |
| Library (sorted photos) | **Read and write** |
| Rest of the share and other shares | **Denied** |

Even if the account were compromised, it could neither modify the originals nor touch the rest of the NAS.

In what follows, replace `<PARTAGE>` (share), `<ENTRÉE>` (input), `<BIBLIOTHÈQUE>` (library) with your real names, and `<NAS>` with the NAS IP address (e.g. `192.168.1.20`).

> The menus below follow the QNAP documentation (QTS 5.x). The exact labels may vary slightly depending on your version; items marked **(to be confirmed)** could not be verified without access to your NAS.

## Step 1 — Back up the configuration

*Control Panel > System > Backup / Restore > Back up system settings* **(to be confirmed)**.

Keep the file outside the NAS. Step 4 changes a global setting: this backup lets you roll back.

## Step 2 — Check that SMB is enabled

*Control Panel > Network & File Services > Win/Mac/NFS/WebDAV > Microsoft Networking* (French: *Services réseau et fichiers > Win/Mac/NFS/WebDAV > Réseaux Microsoft*).

- [ ] **Enable file service for Microsoft networks** is ticked.
- [ ] Authentication: **Standalone server** (local NAS accounts).

If the box was already ticked, do not change anything else here for now.

## Step 3 — Create the `photosort` account

*Control Panel > Privilege > Users > Create > Create a User.*

- [ ] **Username**: `photosort`.
- [ ] **Password**: long (20 characters or more), unique, preferably generated by a password manager. QTS accepts 64 ASCII characters at most.
- [ ] **User group**: none. Above all **not** `administrators`.
- [ ] **Shared folder permissions**: leave empty for now (step 5).
- [ ] **Application privileges** > *Edit*: keep only **Microsoft Networking** (SMB). Deny everything else: File Station, FTP, SSH/SFTP, WebDAV, AFP, NFS, Qsync, multimedia applications **(to be confirmed: exact list depends on your version)**. QNAP recommends denying anything the user does not need.
- [ ] **Quota**: none.
- [ ] Click **Create**.

## Step 4 — Enable advanced folder permissions

*Control Panel > Privilege > Shared Folders > Advanced Permissions*:

- [ ] tick **Enable Advanced Folder Permissions**;
- [ ] **Apply**.

This is a **global** NAS setting: it enables per-subfolder rights for all shares. The existing rights of the shares are not modified, but check 5 (step 9) verifies that nothing broke.

## Step 5 — Set the rights on the share

*Control Panel > Privilege > Shared Folders > Shared Folders*, row `<PARTAGE>` > **Folder Permissions**.

A QNAP rule to know: a **read-only** right on the root applies to all subfolders, and a **deny** on the root blocks everything. To get "read-only" on the input and "write" on the library, we therefore give **read/write on the root**, then restrict in the subfolders.

**5a. Share root** (select `<PARTAGE>` in the left-hand tree):

- [ ] **Add** `photosort` with **Read/Write**.
- [ ] Tick **Only admin can create files and folders** (*Only admin can create files and folders*): `photosort` can no longer create anything at the first level of the share.
- [ ] Tick **Only the owner can delete the contents** (*Only the owner can delete the contents*) and check that the **owner** is `admin`: `photosort` cannot delete or rename the first-level folders.
- [ ] **Never tick** *Special permission*: it gives full access, ignoring all other rights.
- [ ] Leave *Guest access* on **Deny**.
- [ ] **Apply**.

**5b. Input** (`<PARTAGE>/<ENTRÉE>`):

- [ ] **Add** `photosort` with **Read-only**.
- [ ] **Apply**.

**5c. Library** (`<PARTAGE>/<BIBLIOTHÈQUE>`):

- [ ] **Add** `photosort` with **Read/Write**.
- [ ] **Apply**.

**5d. All the other first-level subfolders of `<PARTAGE>`**:

- [ ] **Add** `photosort` with **Deny**, one by one.

**5e. All the other shares on the NAS** (*Shared Folders*, row by row > **Folder Permissions**):

- [ ] **Add** `photosort` with **Deny**.
- [ ] Do the same for shares created later.

Tips:
- Do not go beyond the first or second level of subfolders (QNAP recommendation).
- Avoid *Apply and replace all existing permissions of this folder, files and subfolders* on the root: it would overwrite the existing rights of other accounts on your massive library.
- Optional, hardening: in the *Microsoft Networking host access* drop-down list of the same window, allow only your Mac's IP address.

## Step 6 — SMB options (optional)

*Control Panel > Network & File Services > Win/Mac/NFS/WebDAV > Microsoft Networking > Advanced Options.*

These options are **global**: they also apply to your other devices (TV, scanner, old PC). Only change them if you know they are compatible.

- [ ] **Restrict anonymous users' access to SMB folders**: ticked.
- [ ] **Lowest SMB version**: SMB 3 (includes 3.1 and 3.1.1). macOS supports it. If an old device loses access, restore the default value.
- [ ] **Server signing**: *Sign if the client agrees*. Only enforce signing (*Force signing*) if all your devices support it.
- [ ] Do not tick **Enable SMB daemon in kernel mode** if you want to keep SMB encryption available.

## Step 7 — Mount the share on the Mac

1. Finder > **Go > Connect to Server…** (`⌘K`).
2. Address: `smb://<NAS>/<PARTAGE>` then **Connect**.
3. Choose **Registered User**, enter `photosort` and its password.
4. Tick **Remember this password in my keychain**.
5. The share appears in the Finder and under `/Volumes/<PARTAGE>`.

Known pitfalls:
- macOS often refuses a second mount of the same server with another account. If you are already connected to the NAS with your main account, eject that volume first, or connect with the IP address for one account and the host name for the other.
- Photosort does not mount anything itself and never sees the password: if the share is not mounted, it stops with a message.
- Optional, to avoid leaving `.DS_Store` files on the NAS: in Terminal, `defaults write com.apple.desktopservices DSDontWriteNetworkStores -bool true`, then restart the Finder.

## Step 7bis — Mount the share through Tailscale (Linux)

Prerequisite: [phase 0c](superpowers/plans/2026-11-17-nas-local-connection-plan.md) of the plan is done (NAS and Linux machine in the tailnet, NAS key without expiry, ACLs limited to port 445).

1. Check the connection: `tailscale ping <NAS-MAGICDNS>` must reply **directly**. A DERP relay works but slows SMB down considerably.
2. **GVFS** option (no administrator rights): Dolphin > `smb://<NAS-MAGICDNS>/<PARTAGE>`, account `photosort`. The path is under `/run/user/<uid>/gvfs/`.
3. **cifs** option (administrator rights): `sudo mount -t cifs //<NAS-MAGICDNS>/<PARTAGE> /mnt/photos -o username=photosort,vers=3.0,uid=$(id -u),gid=$(id -g),file_mode=0644,dir_mode=0755` (the password is prompted for; do not write it in the shell history).
4. Then do **step 9** from this mount point (replace `/Volumes/<PARTAGE>` with the real path). **(to be confirmed)**: GVFS and exclusive file creation.

Tailscale rules: no subnet routes or exit node from the NAS, and no Serve or Funnel; only the device running Photosort reaches the NAS, and only on port 445.

## Step 8 — Mount automatically at startup (optional)

System Settings > General > **Login Items**: drag the mounted volume into the **Login Items** list.

## Step 9 — Check the rights (5 checks)

Preparation: with your **administrator account** (File Station), drop a text file `test-lecture.txt` into `<ENTRÉE>`. **Never try to delete a real photo** for this test.

In Terminal, with the share mounted by `photosort`:

```sh
cd "/Volumes/<PARTAGE>"

# 1. must FAIL (Permission denied / Read-only)
touch "<ENTRÉE>/essai.txt"

# 2. must FAIL
rm "<ENTRÉE>/test-lecture.txt"
mv "<ENTRÉE>/test-lecture.txt" "<ENTRÉE>/renomme.txt"

# 3. must SUCCEED
touch "<BIBLIOTHÈQUE>/.essai-photosort" && rm "<BIBLIOTHÈQUE>/.essai-photosort"

# 4. must FAIL (access denied)
ls "<AUTRE-SOUS-DOSSIER>"
touch "essai-racine.txt"
```

Then:

- [ ] **1. Creation in the input**: denied.
- [ ] **2. Deletion and renaming in the input**: denied.
- [ ] **3. Creation then deletion in the library**: succeed.
- [ ] **4. Other subfolders, share root and other shares**: denied (also try `smb://<NAS>/<AUTRE-PARTAGE>` in the Finder).
- [ ] **5. Existing accounts**: the iPhone's automatic backup keeps working (run one and check that a new photo arrives), QuMagie still shows your photos, and your main account still accesses its folders.

**All checks must pass.** If 1 or 2 succeeds, the account has too many rights: do not run Photosort, fix step 5 (most often, a right inherited from the root or from a group).

Then delete `test-lecture.txt` with the administrator account.

## Step 10 — After the first real copy

Once Photosort has copied its first photos (phase 6 of the plan), check from your **main account** (not `photosort`):

- [ ] you can open and read the photos copied into `<BIBLIOTHÈQUE>`;
- [ ] QuMagie indexes them.

If they are unreadable, it means the files are created with mode `0600`: tell me, the plan provides an option to create the files with `0644`.

## Rules to remember

- **Never expose SMB (port 445) to the internet** or forward it from the router. Remote access goes through Tailscale only (ACLs limited to port 445), never through a port forward; no Funnel, no Serve, no subnet routes.
- The `photosort` account is only for Photosort. Do not reuse it elsewhere.
- Change its password if in doubt, then update the keychain.

## Rollback

- Remove `photosort` from the permissions of each folder, or **delete the account** (*Privilege > Users*).
- To return to the previous state: restore the file from step 1, or untick *Enable Advanced Folder Permissions* (step 4). The QNAP documentation notes that this may change rights at the subfolder level: then check your existing access.
